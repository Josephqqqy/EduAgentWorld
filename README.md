# AgentWorld 教育助手环境框架

本目录面向中国教育场景，统一组织学生端和教师端的 AgentWorld 环境。当前规划包含两个一级主题、六个二级主题体系和 49 个三级环境：学生端 25 个，教师端 24 个。每个三级主题都可以独立实现为一个包含数据库、工具集、依赖图和可验证任务的环境。

## 一级主题

- `StudentAssistant`：学生教育助手，支持学习内容获取、练习作业、考试升学、学习诊断、资料管理和综合素养。
- `TeacherAssistant`：教师教育助手，支持教学资源、备课设计、作业测评、学情干预、班级管理和教师发展。

## 目录结构

│   ├── schemas/                    # 公共 JSON Schema

│   │   ├── A/                      # 学习内容获取与表达
│   │   ├── B/                      # 练习、作业与实验

│   └── TeacherAssistant/           # 一级主题：教师教育助手（24 个三级环境）
│       ├── A/                      # 教学内容与资源
│       ├── B/                      # 备课与课程设计

## 单个环境骨架

每个三级环境目录统一包含：

```text
<environment>/
├── raw/                            # 该环境的原始数据快照
├── normalized/                     # 规范化实体和业务状态
├── indexes/                        # 该环境的查询和统计索引
├── fixtures/                       # 最小可复现种子数据
└── tests/                          # 工具和状态迁移测试
```

实现阶段可在环境目录中增加 `env.py`、`schema.sql` 或 `schema.json`、`tools.py`、`seed.py`、`dependencies.json` 和任务样例。工具应从真实业务流程反推，定义稳定参数、返回结构、错误码、读写属性和单元测试，而不是机械暴露万能 CRUD。

## 数据与环境边界

原始教育资料和生产系统数据在评测时转换为固定离线快照；学生、教师和家长个人信息使用脱敏 ID。学生端与教师端可以共享 `student_id`、`teacher_id`、`course_id`、`problem_id`、`knowledge_point_id` 和 `source_id` 等稳定实体，但分别维护会话、成绩、计划、诊断、干预和权限状态。所有写操作需要保留版本与审计记录。
